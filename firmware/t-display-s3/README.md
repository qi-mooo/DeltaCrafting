# DeltaCrafter Monitor

LILYGO T-Display-S3 固件，通过 Wi-Fi 显示 DeltaCrafter 四个制造设施、中文物品名、
制造倒计时与自动循环状态。使用桌面客户端内置的配对 API。

## 使用 CI 固件

在 GitHub Actions 的 CI 页面下载 `DeltaCrafter-esp32s3-<提交哈希>` artifact，
解压其中的 `DeltaCrafter-esp32s3.zip`。包内包括各分区镜像、烧录地址与 SHA-256 清单、
烧录和配置工具、ELF 及固件源码。固件不包含个人 Wi-Fi 密码或配对密钥。
完整包同时包含四宫格监控和静音/音频桥两个程序，必须按清单一起烧录。

## Wi-Fi 在线更新

从 `axeuh-tools-v16` 开始支持在线更新。旧版需要先通过 USB 烧录一次完整的 v16 或更高版本；
之后不必再按 BOOT 进入下载模式。Windows 客户端需要 0.4.12 或更高版本，并启用设备 API 和允许设备控制。

1. 更新并保持 Windows 助手运行。CI 与正式发布的客户端包含同一次构建的 `Firmware/DeltaCrafter-esp32s3.zip`，启动时校验并准备固件；也可在「设置 → T-Display-S3 → S3 在线固件」导入新的 ZIP。
2. 在 S3「全局设置 → 固件更新」检查版本，再选择「安装」。同版本允许重新安装；拒绝降级、不兼容机型、分区布局或更新协议。
3. 四宫格先更新静音分区，然后自动重启，由静音程序更新四宫格分区。屏幕显示两阶段进度，完成后自动返回主界面。

v17 修复第二阶段进度闪烁：复用静音程序已有帧缓冲，整帧提交画面，不在 LCD 上逐项清屏重绘；
连续进度最多每秒刷新 10 次，状态变化和完成提示立即显示。
v18 将当前版本移至「固件更新」标题栏右侧，与标题同一行显示。
v19 将安装项上移到标题栏下方，更新菜单复用全局设置的 Axeuh 焦点移动与伸缩动画；返回全局设置时使用返回方向的切页动画。
v20 新增「全局设置 → 屏幕亮度」，四宫格、静音程序和在线更新页面共用已保存的亮度。
v21 新增「全局设置 → 自动休眠」，关闭 Wi-Fi、背光和屏幕供电后进入 ESP32 深度休眠，GPIO 14 唤醒。
v22 为四宫格选框和进度条留出间隔，焦点动画经过时也不会遮挡进度条；「静音控制」更名为「声音控制」，
移除 RESET 退出提示，进入声音控制后不再自动休眠，手动熄屏仍保持联网和音频桥。
v23 在四宫格未休眠时后台连接声音控制，进入后直接访问已配对电脑；USB 主机识别设备后才开启音频转发，
拔出或挂起时关闭转发，音量、静音和电平曲线仍通过 Wi-Fi 工作。
v24 将超出一屏的列表焦点固定在中间，列表随按键平滑滚动，上下相邻选项完整可见；
制造物品、全局设置、亮度、休眠和工具长列表统一使用该规则，短菜单仍紧接标题排列。

更新只写两个应用分区，不改分区表、引导程序和 Wi-Fi/配对配置。每个映像核对大小、SHA-256，
并由 ESP-IDF 校验后才选择启动。更新期间保持供电和网络：第一阶段失败仍可使用四宫格并重新检查安装；
第二阶段断线或 RESET 后保留更新程序，网络恢复后自动重试，完成前不切回未写完的四宫格。
正常使用静音工具时仍然只有 RESET 退出。更新中的两份映像按包 ID 固定，助手保留旧包以支持中断恢复。

固件下载沿用已配对的局域网 API：`GET /api/v1/firmware` 和
`GET /api/v1/firmware-image?bundle=<SHA-256>&role=monitor|audio`，两者均要求配对密钥和允许控制。
这套更新用于同一板型和固定分区的应用升级；更改引导程序、分区表或无法启动的损坏固件仍需 USB 恢复。

## USB 首次安装

安装 Python 3 后，在解压目录执行：

```bash
python -m pip install esptool==4.5.1 pyserial==3.5
python flash.py --port COM5
python configure.py --port COM5 --wifi-ssid Your-WiFi --base-url http://192.168.1.100:17890
```

Windows 端口使用实际的 `COM` 名称；macOS 使用 `/dev/cu.usbmodemXXXX`。
配置工具会隐藏输入 Wi-Fi 密码和桌面配对密钥，通过 USB 保存到板上 NVS，保存后自动重启。
以后更换网络、电脑地址或密钥只需重新运行配置工具。需要 2.4 GHz Wi-Fi。

烧录工具先验证镜像校验和，然后按清单写入对应分区，不执行整片擦除。不要把
`firmware.bin` 写到地址 0。进入下载模式：按住 BOOT，按一下 RESET，再松开 BOOT；
烧录完成后按一下 RESET 运行；工具不自动切换下载/运行模式。配置时设备必须运行固件，关闭其他串口监视器。

桌面端在「设置 → T-Display-S3」开启 API 并复制配对密钥。电脑需允许本地子网访问
对应 TCP 端口。默认只读监控，按键控制另需开启「允许设备控制」。

## 从源码构建

需要 PlatformIO 6.1.19；板级定义和显示驱动使用固定版本的 LILYGO 仓库：

```bash
git clone https://github.com/Xinyuan-LilyGO/T-Display-S3.git .firmware-sdk
git -C .firmware-sdk checkout 5c7b97a42e6ed4ec299004f0578c097ece412d6f
export TDISPLAY_S3_DIR="$PWD/.firmware-sdk"
pio run -d firmware/t-display-s3/audio
pio run -d firmware/t-display-s3
python firmware/t-display-s3/tests/run_native.py
```

命令在 DeltaCrafting 仓库根目录执行。也可将 `TDISPLAY_S3_DIR` 指向已有的同版本
T-Display-S3 仓库。Windows PowerShell 使用 `$env:TDISPLAY_S3_DIR = '板级仓库绝对路径'`。
打包文件位于工程的 `.pio/build/deltacrafter-monitor/DeltaCrafter-esp32s3.zip`。
在发布包的 `source` 目录重建时，先运行 `pio run -d audio`，再运行 `pio run -d .`。
工程拒绝带 `include/config.local.h` 的发布构建；请使用 USB 配置凭据。
默认使用新版 LCD 初始化，早期面板可在编译参数加入 `-DDELTA_LCD_NEW_PANEL=0`。
构建会检查项目源码的单函数栈帧，超过 3072 字节即失败；`.su` 文件保留编译器栈占用报告。
该检查不能替代真机验证：网络任务使用 12 KB 栈，仍需检查最深调用链运行后的剩余空间。

## 屏幕与按键

监控程序所有页面使用黑底白字。主界面按游戏中的位置排列：左上技术中心、右上工作台、
左下制药台、右下防具台，底部是游戏状态和电池图标。选中项使用粗外框和角标，进度条与选框之间保留黑色间隔。
UI 使用固定版本 Axeuh_UI，焦点平滑移动和伸缩，进入/返回页面有滑动过渡，目标刷新率 60 FPS。
长列表的选框固定在可见区域中间，条目平滑移动；进入时已选物品直接居中，首尾保留空白。
主界面长物品名在名称行内向左循环滚动，尾部留 24 像素空隙后接回开头；每圈回到开头停留 2 秒再滚动，首次显示也停留 2 秒。短名称保持静止。
名称变更或返回主界面时从开头显示，状态轮询不重置滚动，不遮挡倒计时和进度条。
每格底部显示制造进度条：由客户端确认开工时间与 OCR 剩余时间计算；接管已有任务、
填充宽度 = (总时长 − 剩余时间) ÷ 总时长。总时长未知时保留空框；离线时冻结进度。
在线时倒计时归零显示「待收取」并填满进度条；未到期显示「制造中」。
「空闲中」由客户端识别确认，不通过倒计时推断。停用计划也显示设施实际状态。
空闲设施的物品名称行留空；下一轮计划仍保留在设施设置中。
到期显示不修改客户端保存的观测或触发领取；自动执行仍先识别游戏画面。
电池图标按 GPIO 4 校准电压显示四格电量，不显示百分比；无效读数显示叉号。
电压是近似电量，USB 充电时可能偏高，硬件无法可靠识别所有未接电池情况。

| 按键 | 单击 |
| --- | --- |
| GPIO 0（BOOT） | 进入选中菜单 / 确认 |
| GPIO 14 | 下一项，循环选择 |

普通菜单按住只触发一次。仅制造物品列表使用 GPIO 0 长按 0.8 秒保存，成功后返回设施设置；
短按物品不保存，选中「返回设施设置」可单击退出。开机时按住 BOOT、按住进入列表均不会误保存。

主页选择顺序：技术中心 → 工作台 → 制药台 → 防具台 → 状态栏左侧 → 工具与电量。
选中状态栏左侧时临时显示「进入设置」，移开恢复游戏状态与下次时间。
右侧「工具」和电量共用一个选择区域，确认进入工具菜单。
选中设施后按确认打开启用/停用和制造模式菜单；自定义模式额外显示「制造物品」。
每小时利润最高模式额外显示「刷新利润物品」：仅查询该设施行情并更新下一轮推荐，
不领取、不取消正在制造的任务。菜单底部显示刷新结果；失败保留原选择。
进入后从电脑读取该设施配方目录并立即定位到已选项，GPIO 14 循环浏览；保存与 App 计划页同步。
物品显示统一等级标签，如「5级 .300BLK」；确认与定位使用原始物品身份，区分同名不同等级。
读取或保存失败会留在列表并显示原因；最大 254 项，超过时提示在电脑选择，不截断目录。
选中状态栏后按确认打开全局菜单：自动循环、Steam 游戏检测、收取后行为、开始制造、
识别当前任务、关闭游戏、刷新数据、固件更新、屏幕亮度、自动休眠、返回。超过一屏时菜单自动滚动，焦点保持可见。
「屏幕亮度」提供 10%～100% 十档，默认 100%。进入时定位到已保存亮度；GPIO 14 循环选择并即时预览，
GPIO 0 单击保存后返回，选「返回（不保存）」恢复原亮度。设置保存在本机，离线或电脑只读时也能调整；
重启、切换静音程序、静音程序关闭屏幕后再点亮及 OTA 更新后均保留。沿用 Axeuh 菜单焦点和切页动画。
「自动休眠」提供关闭、30 秒、1/2/5/10 分钟，默认 1 分钟，单击确认保存，重启后保留；仅作用于四宫格程序。
按键操作重置计时，后台轮询不重置。到时等待当前请求结束，关闭 Wi-Fi、背光及 GPIO 15 屏幕供电，
进入深度休眠；CPU 和状态刷新均停止，不设置定时或网络唤醒，电脑端任务继续运行。
按 GPIO 14 循环键唤醒并重新联网、返回四宫格主界面；唤醒按键及其长按、松开不会触发操作。
进入声音控制后不会自动休眠，手动熄屏仍保持 Wi-Fi、声音控制和 USB 音频桥运行；RESET 返回四宫格后恢复已保存的休眠设置。
OTA 更新及未完成的恢复过程禁止自动休眠。实际休眠电流受板载稳压器、充电电路和 USB 供电影响，尚未实测。
「刷新数据」请求电脑更新三角洲数据帝四设施物品列表，菜单底部显示刷新结果，不改变制造计划。
刷新中不重复请求；浏览菜单和定时轮询不会查询数据帝。Token 在电脑设置页保存。
「关闭游戏」关闭本机客户端（包括最小化窗口），不受 Steam 暂缓限制；任务执行中须先在助手停止。
「开始制造」按 App 的启用设施计划执行一轮；「识别当前任务」只观察四设施，不领取或开工。
两者均经过客户端原有 Steam 检测、校准、更新和任务互斥检查，不改变自动循环开关。
请求只发送一次，菜单底部显示提交结果与客户端状态。
打开菜单不需要控制权限，保存需要电脑开启「允许设备控制」；设置成功后从 API 刷新确认，
超时不自动重试。只有在全局菜单确认操作项才会提交任务。

每 3 秒轮询；断线保留四格旧数据，停止倒计时，底部显示离线。
状态栏左侧显示「游戏中 / 未在游戏中 · 下次 HH:mm」，右侧显示「工具」和电池图标；下次执行时间采用电脑本地时区；
未计划下次执行或离线时显示 `--:--`。仅三角洲行动显示游戏中，其他游戏忽略。
游戏状态来自客户端独立的 Steam 查询，每 30 秒更新，不使用“自动任务运行”代替。
旧客户端缺少状态字段时显示游戏状态查询中，并提示升级后才能保存设置。
HTTP 在独立任务中运行，游戏查询失败或过期不会显示为未在游戏。

串口 115200 波特率发送一行 `{"command":"info"}` 可读取配置状态、Wi-Fi IP、
API 在线状态、设施数量、固件标识 `axeuh-tools-v24`、按键映射和可用内存，不会返回密码或密钥。
`soundControlOnline` 表示后台最近一次声音控制查询成功且未过期，四宫格后台不启用音频桥。
`updaterAbi` 表示在线更新协议版本，`otaPending` 表示是否有尚未完成的更新。
串口维护命令 `{"command":"firmware-check"}` 打开更新页并检查电脑提供的固件；检查成功后，
`{"command":"firmware-install"}` 开始同一套在线更新流程。
`loopMinFreeStack` 和 `networkMinFreeStack` 是两个任务运行以来的最小剩余栈空间，单位为字节。

工具菜单提供今日密码、当前集市物品、改枪码和声音控制。进入选择菜单不请求数据。
今日密码一次返回所有地图，列表显示地图名和密码；详情顶部地图名、中央大号密码、底部日期。
集市使用客户端磁盘缓存，有效期内反复进入或重启客户端不重复查询数据帝；过期后下次进入才更新。
集市详情左侧显示物品图片，右侧名称和返回，顶部价格、底部有效期；图片仅打开详情时下载并缓存。
改枪码先选烽火地带/大战场，再选热门/按枪械查询；前两级菜单不查询数据。
枪械目录使用 V2 筛选接口并在本次客户端运行期间缓存，选中枪械后才请求对应方案；方案均按使用人数排序。
列表包含作者，顶部标题带模式和页码，底部固定图标栏提供上一页、下一页、刷新和返回。
查看详情和返回列表不重复查询；确认方案打开详情并复制完整代码到 Windows 剪贴板，详情末尾可再次复制。
复制需要电脑开启允许设备控制；查询与复制失败均显示原因，用户手动重试。
发送 `{"command":"screen"}` 可读取当前画面：一行 JSON 头后紧跟 108800 字节 RGB565 小端数据。
明文 HTTP 仅用于可信局域网，不要做公网端口转发。

## 声音控制 / 音频桥

在「工具 → 声音控制」按确认，设备自动重启切换到完整的 WindowsMuteController 程序。
保留原程序的彩色界面、电平历史、音量和 USB UAC1 单声道麦克风功能。此时四宫格程序
已经退出，其 API 轮询和按键菜单均停止；无需电脑助手在线即可进入。
四宫格未休眠时每 3 秒通过 HTTP 读取已配对电脑的声音状态，只访问 8765 控制接口，
不注册音频桥、不接收 PCM，也不占用其他设备的音频目标；后台查询不会延长自动休眠计时。
进入声音控制时复用电脑地址和当前 Wi-Fi 接入点，Wi-Fi 恢复后可直接操作，不等待音频广播发现。
两个独立程序仍需重启切换，因此存在短暂的 Wi-Fi 重连；接入点变化时自动回退普通联网。
声音程序通过局域网发现接收电平曲线，并在 USB 主机完成枚举后才开放 PCM 音频端口；
电池或仅供电的 USB 不启用音频转发。拔出或挂起立即关闭 PCM，重新插入后自动恢复，
音量、静音和电平曲线始终独立于 USB；USB 初始化失败也不会阻断声音控制。
Windows 助手首页右上角显示当前静音状态并可直接切换；不再需要单独启动 `TDisplayAudioBridge.exe`。
电脑仍需运行该服务（HTTP 8765、发现 UDP 40100、音频 TCP 40101），无需更改 DeltaCrafter API。

| 按键 | 静音程序中的功能 |
| --- | --- |
| GPIO 0 短按 | 切换电脑静音 |
| GPIO 0 长按 | 连续降低音量 |
| GPIO 14 短按 | 开关屏幕 |
| GPIO 14 长按 | 连续增加音量 |
| RESET | 重启返回四宫格 |

静音程序没有返回菜单或按键组合；重启/断电再上电回到四宫格。进入时恢复下一次启动的
监控分区，当前静音程序继续运行。两者使用相同的 16 MB 分区表：监控位于 `0x10000`，
静音位于 `0x650000`，NVS 保持在原地址。静音程序使用 Arduino-ESP32 3.3.9 提供 USB Audio，
监控程序保持 Arduino-ESP32 2.0.14；打包时核对两个分区表完全一致。
静音固件缺失或校验失败时留在工具菜单并提示重刷完整包。
