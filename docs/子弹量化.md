# 子弹量化（Windows 0.6.0）

`leitingquant` 源码单独保留在相邻的 `code/leitingquant`。Windows 助手使用原生 WinUI 页面融合行情分析、自选计划和持仓收益；均线、RSI、波动率等算法改编自该项目，版权与 MIT 正文随发布包保留。

## 使用

1. 在现有设置页填写数据帝 Token，打开左侧「子弹量化」。
2. 选择子弹等级，点击刷新。一次请求得到该等级全天低价预测；选择时段、搜索、排序和修改预算在本地完成。
3. 点击一条预测，查看时段、价格和图片，填写买入限价、卖出目标、数量与卖出综合手续费，保存自选计划。
4. 「查询历史与指标」单独请求该物品近 24 小时分钟数据，绘制曲线，计算最近 20 个有效采样的 MA、EMA、RSI、最低/最高、区间位置、涨跌和标准差。不足 20 个采样明确显示不足。
5. 使用「记录实际买入」记入实际成交价。在「持仓」中填写实际卖出价格和数量，通过「记录实际卖出」结算，支持部分卖出。
6. 「策略选品」使用已查询等级的当日预测作为物品目录。点击「刷新行情 (N 项)」按物品去重后查询历史，一项一次请求，可取消；失败时停止剩余请求并保留已完成缓存。
7. 切换策略在本地计算，不联网。详情中可运行历史回测；齿轮按钮设置最低目标收益、数量上限、采样数、手续费、止盈止损与滑点。
8. 「持仓」的刷新按钮只查询未平仓物品。浮盈使用最新实际报价扣除该笔记录的手续费，数据缺失或过期时显示未估值。

手续费默认 13%，使用前按实际游戏手续费调整。税后收益 = 数量 ×（卖出价 ×（1 − 手续费比例）− 买入价）。统计仅基于已记录的真实成交；预测低价和卖出目标不会被记为实际利润。历史曲线使用采样顺序横轴，具体首尾时间显示在曲线上方。

预测缓存、自选、成交记录、量化参数与最近 200 项历史行情保存到 `%LocalAppData%\DeltaCrafter\quant.json`；文件损坏时提示错误，保留原文件。关闭页面取消未完成请求，失败保留上次有效缓存。启动客户端和切换页面不会自动收费查询，跨日缓存显示过期。预测接口未提供源日期，本地日期仅表示获取日，不是数据源保证。

## 策略与回测

所有策略均要求实际最新报价、预算可买至少一发，以及达到最低税后目标空间。分钟历史区间以接口实际返回的时间为准，没有七日行情时不使用七日指标。利润优先以历史最高价为目标，其他策略使用历史高低价中值；目标空间不是保证收益。

| 策略 | 入场条件与排序 |
| --- | --- |
| 综合选品 | 低于均线、RSI < 50、区间位置 < 50%；按预算内税后目标利润排序 |
| 利润优先 | 低于历史高价；按税后目标收益率排序 |
| 动量追涨 | 指标周期上涨、最新价高于均线且高于上一采样；按涨幅排序 |
| 低位抄底 | RSI ≤ 35、区间位置 ≤ 25%；按相对历史中值的折价排序 |
| 超跌反弹 | 低于均线、最新价较上一采样回升、RSI < 50；按折价减周期涨幅排序 |
| 区间套利 | 存在价格波动、区间位置 ≤ 25%；按历史振幅排序 |

报价时间按北京时间解析，缺失、未来或乱序数据不产生当前策略信号。超过 30 分钟的报价只保留为历史展示，需手动刷新才参与估值。默认净收益止盈 10%、净收益止损 20%、移动止盈回撤 3 个百分点；阈值设为 0 关闭对应提示。移动止盈仅计算买入之后的已缓存历史高点，无法涵盖未查询到的更早持仓区间。

回测使用同样的入场与退出规则。信号只查看当前及之前的采样，在下一有效采样按整数数量成交，买入和卖出分别计入滑点，卖出再扣除手续费；末尾结算剩余持仓。最大回撤按每个采样的净变现权益计算。回测不模拟交易量、成交深度、库存和上架等待，结果不改变实际账本。

## 数据源

| 用途 | 数据帝接口 | 请求时机 |
| --- | --- | --- |
| 当日低价预测 | `/v1/sjz_api/ammo_day?grade=0..6` | Windows 点击刷新所选等级 |
| 历史曲线 | `/v1/sjz_api/minute?id=oid` | Windows 点击查询历史与指标 |
| 策略与持仓批量行情 | `/v1/sjz_api/minute?id=oid` | Windows 点击刷新行情，每个不同物品一次 |

`ammo_day` 中的 `id` 用于自选与成交身份，`oid` 是分钟曲线使用的第三代 ID，不能混用。`.300BLK_3/4/5` 的原始名称与身份保留，界面分别显示「3/4/5级 .300BLK」。0 级就是 0 级，并非全部等级。查询只请求一次，不自动重试或预取其他等级。

实现遵循公开接口文档：
- [今日倒子弹低价预测](https://work-api.apifox.cn/399848912e0.md)
- [价格曲线·分钟刻度](https://work-api.apifox.cn/397280031e0.md)

## 后续 API 接口

`GET /api/v1/quant` 沿用设备 API 的 `Authorization: Bearer <配对密钥>`，不需要开启远程控制。响应包含：

```json
{
  "schemaVersion": 1,
  "forecasts": [],
  "watchlist": [],
  "trades": [],
  "options": { "strategy": "SMART", "minimumReturn": 3, "maxQuantity": 999, "takeProfit": 10, "stopLoss": 20, "trailingStop": 3, "slippage": 0, "period": 20 },
  "candidates": [],
  "positions": [],
  "summary": {
    "openCost": 0,
    "realizedProfit": 0,
    "todayProfit": 0,
    "winRate": 0,
    "maxDrawdown": 0,
    "closedCount": 0,
    "openCount": 0
  }
}
```

`GET /api/v1/status` 增加 `quantSupported: true`。快照读取仅访问本地缓存，不产生数据帝查询，不包含 Token。核心通过 `IAmmoMarketSource` 隔离提供方，通过 `QuantCoordinator` 共用查询与记账逻辑，后续 S3/其他界面可复用。没有接入或调用 LLM。

本阶段没有迁入雷霆可视化流程编辑、脚本节点与游戏自动买卖，也未变更 S3 固件。
